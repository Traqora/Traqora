# Booking Lifecycle Recovery & Idempotency

## Overview
To prevent duplicate supplier booking submissions and ambiguous request retries, Traqora uses idempotent supplier reference reconciliation.

## Idempotency Mechanism
- Every booking request generated by the client includes a unique supplier reference / idempotency key.
- The booking lifecycle handler tracks submitted supplier references in persistent storage.
- On retry or duplicate submission with the same supplier reference, the contract/API reconciles the state and returns the existing valid booking receipt instead of duplicating the transaction.

## Recovery Steps
1. Check the existing booking receipt via the transaction hash or supplier reference.
2. If reconciliation succeeds, resume the escrow and ticket issuance flow.
3. If an error occurs, inspect contract logs for `BookingAlreadyRegistered` or equivalent guard errors.
